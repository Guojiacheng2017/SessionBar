# SessionBar Details Tab Boundaries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved Details tab boundary refinement so Overview, Activity, Flow, and Raw each render distinct terminal-sized session information.

**Architecture:** Keep the change inside the existing `sessionInspector.ts` rendering boundary. OpenTUI continues to render `StyledText` returned by `buildSessionDetailChunks`; tests assert behavior through the compiled `dist/sessionInspector.js` API.

**Tech Stack:** TypeScript, Node test runner, OpenTUI `StyledText` chunks.

---

## File Structure

- Modify `types.ts`: add optional deterministic `plan_signal` and `flow` fields for future hook adapters without requiring server changes.
- Modify `sessionInspector.ts`: update tab enum from `events` to `flow`, replace Overview Primary Stage/Priority Rail rendering with compact state sections, make Activity a short history view, add Flow graph/fallback rendering.
- Modify `openTuiMonitor.ts`: titles continue to derive from `DetailTab`, so only the `Flow` tab name should flow through.
- Modify `test/sessionInspector.test.mjs`: rewrite old Primary Stage/Priority Rail assertions into the new tab boundary assertions.
- Generated by build: `dist/sessionInspector.js`, `dist/types.js`, `dist/openTuiMonitor.js`.
